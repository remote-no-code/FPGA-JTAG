# Task 3B – JTAG Debug Clock Domain Crossing (CDC)

> **Implementation and verification of a toggle-based two-flip-flop synchronizer for safely transferring JTAG debug requests between asynchronous clock domains using Verilog HDL.**

---

## Overview

Modern digital systems frequently operate with multiple independent clock domains. When signals are transferred between these asynchronous domains, improper synchronization can lead to **metastability**, missed events, or unreliable system behavior.

This project implements a **Clock Domain Crossing (CDC)** mechanism for a JTAG debug interface. The objective is to safely synchronize asynchronous debug requests generated in the **JTAG clock domain (TCK)** with the **processor clock domain (CLK)** while preserving event integrity.

The design employs a **toggle-based synchronization technique** together with a **two-flip-flop synchronizer** to reliably transfer the following debug requests:

* **HALT**
* **RESUME**
* **RESET**

The CDC module is implemented in **Verilog HDL** and verified using a self-checking testbench developed with **Icarus Verilog**. Functional behavior, synchronization correctness, and pulse generation are validated using **GTKWave**.

---

## Integration Status

This project verifies the **Clock Domain Crossing (CDC)** module as a **standalone verification design**.

The debug requests (`HALT`, `RESUME`, and `RESET`) emulate outputs that would normally be generated by the **JTAG TAP Controller developed in Task 3A**. During verification, these requests are generated by the testbench, while a simplified processor model validates the synchronized outputs by monitoring the **Program Counter (PC)** and **halted** state.

This modular verification approach isolates the CDC logic, allowing it to be thoroughly validated before integration with a complete **JTAG Debug Module** and a **RISC-V processor core**.

# Clock Domain Crossing (CDC)

Clock Domain Crossing (CDC) refers to the transfer of signals between circuits operating on different clock sources. Since the clocks are asynchronous, transferring signals directly can violate setup and hold timing requirements, potentially resulting in metastability or missed events.

To solve this problem, this design adopts a **toggle-based synchronization mechanism**. Instead of sending a short pulse directly across the clock boundary, every debug request toggles a register in the JTAG clock domain. This toggle is synchronized into the processor clock domain using a **two-flip-flop synchronizer**, after which an **edge detector** regenerates a clean single-clock pulse.

This approach provides reliable event transfer while significantly reducing the probability of metastability propagating into downstream logic.

The architecture is divided into three functional regions that together ensure reliable synchronization of debug requests across asynchronous clock domains.

---

### 1. JTAG Clock Domain (TCK)

The **JTAG TAP Controller** operates in the TCK domain and generates asynchronous debug requests based on decoded JTAG instructions.

| Signal                 | Description                                 |
| ---------------------- | ------------------------------------------- |
| `debug_halt_req_tck`   | Requests the processor to halt execution.   |
| `debug_resume_req_tck` | Requests the processor to resume execution. |
| `debug_reset_req_tck`  | Requests a processor reset.                 |

Since these requests originate in a different clock domain, they cannot be used directly by the processor.

---

### 2. Clock Domain Crossing Logic

Each debug request passes through three processing stages.

#### Toggle Generation

Every incoming debug request is converted into a **toggle event** instead of a narrow pulse. Since toggle events persist until sampled, they can be detected reliably even when the destination clock is asynchronous.

#### Two-Flip-Flop Synchronizer

The generated toggle is synchronized into the processor clock domain using a standard **two-flip-flop synchronizer**, significantly reducing the probability of metastability.

#### Edge Detector

The synchronized toggle is monitored by an **edge detector**, which regenerates a clean **single-clock pulse** in the processor clock domain.

> **Why use a toggle-based synchronizer?**
>
> A single-clock pulse generated in the TCK domain may occur entirely between two processor clock edges and therefore be missed. Converting the request into a toggle guarantees that the event persists long enough to be detected after synchronization.

---

### 3. Processor Clock Domain (CLK)

The synchronized debug pulses are received by the processor model, where they control execution.

| Debug Request | Processor Action                                                             |
| ------------- | ---------------------------------------------------------------------------- |
| **HALT**      | Stops Program Counter updates and halts execution.                           |
| **RESUME**    | Restarts execution by allowing the Program Counter to continue incrementing. |
| **RESET**     | Clears the Program Counter and returns the processor to its initial state.   |

# Implementation

## CDC Module

The `jtag_debug_cdc.v` module implements:

* Toggle generation
* Two-flip-flop synchronizers
* Edge detection
* Synchronized HALT, RESUME and RESET outputs

Each synchronized output is asserted for exactly **one processor clock cycle**, making the module suitable for processor control logic.

---

## Testbench

A comprehensive self-checking testbench verifies the CDC module using independent clock domains.

Features include:

* Independent **TCK** and **CLK** generation
* Simplified processor model
* Program Counter monitoring
* HALT verification

* RESET verification
* One-clock pulse verification
* Automatic PASS/FAIL reporting

A complete **JTAG Debug Clock Domain Crossing (CDC)** mechanism was successfully designed and verified using Verilog HDL.

The self-checking verification environment confirms correct synchronization of HALT, RESUME, and RESET requests while validating processor state transitions and Program Counter behavior.

This modular CDC implementation provides a robust foundation for future integration with the JTAG TAP Controller developed in **Task 3A** and a complete **RISC-V debug subsystem**.
